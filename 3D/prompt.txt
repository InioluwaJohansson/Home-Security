# HanssonHub 3D House Builder — Google AI Studio Implementation Prompts
Use these prompts sequentially. Each prompt assumes the existing frontend project and prior prompt outputs are retained. Do not replace the existing authentication flow or backend.


========================================================================================
PROMPT 01 - Project audit and integration guardrails
========================================================================================
You are extending the existing HanssonHub Google AI Studio frontend. First inspect the existing React/TypeScript project, routing, design system, API client, authentication state and current login flow. Do not replace working features. The backend is the existing Home-Security ASP.NET Core API, not a new app. Preserve the existing login endpoint POST /Home_Security/User/Login and its response contract; the returned JWT is in response.token. Do not invent login DTO fields: inspect existing code and reuse it. Store/use the existing token through the app's current auth mechanism. Every spatial HTTP request must send Authorization: Bearer <token>. Never ask the user for PersonId; backend derives it from JWT. Do not build UI for hidden scene data or bypass server visibility filtering. Output an integration plan and list discovered existing files before editing.

========================================================================================
PROMPT 02 - API client and JWT handling
========================================================================================
Implement a typed spatial API client using the app's existing API base URL and auth/token store. The login response's `token` field is the bearer token. Add an interceptor/wrapper that attaches `Authorization: Bearer ${token}` to every spatial request, handles 401 by using the existing logout/session-expiry flow, and never logs tokens. Do not create a second login flow. Existing backend login: POST /Home_Security/User/Login; its exact body must reuse the existing login form/DTO. Example curl after the user logs in:
curl -X GET "$API_BASE/Home_Security/Spatial/Properties" -H "Authorization: Bearer $TOKEN"
Create typed functions for GET Properties, POST Properties, POST Buildings, POST Floors, floor section/room bindings, geometry, placements, scene retrieval and placement deletion.

PROMPT 03 - Property and building setup
========================================================================================
Build the property setup screen. Use authenticated APIs only. Create property:
curl -X POST "$API_BASE/Home_Security/Spatial/Properties" -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"name":"Main Residence"}'
Create building:
curl -X POST "$API_BASE/Home_Security/Spatial/Buildings" -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"propertyId":1,"name":"Main Building","baseElevation":0}'
Support multiple buildings per property. Never send PersonId; backend gets it from JWT. Display server validation errors clearly.

PROMPT 04 - Floor levels and existing sections/rooms
========================================================================================
Implement floor management with Underground, Ground and Top as suggested labels, but allow user-defined names and elevations. Create floor:
curl -X POST "$API_BASE/Home_Security/Spatial/Floors" -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"buildingId":1,"name":"Underground","levelIndex":-1,"elevation":-3.2,"defaultCeilingHeight":2.7}'
Reuse existing Home Security sections and rooms; do not create duplicate room/section records. Bind a section:
curl -X POST "$API_BASE/Home_Security/Spatial/Floors/1/sections" -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"sectionId":1}'
Bind a room directly to a floor only when existing Room.SectionId is null:
curl -X POST "$API_BASE/Home_Security/Spatial/Floors/1/rooms" -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"roomId":1,"sectionId":null}'
A room may be linked through a section or directly to a floor, not both.

Build the 3D scene using the project's existing supported stack; use Three.js if not already present. Coordinate convention: right-handed, Y-up, metres; X/Z horizontal. Persist rotations as quaternions. Use parent-relative transforms and a property world root. Create scene loading from:

PROMPT 06 - Room outline editor and generated geometry
========================================================================================
Implement a room-outline editor supporting irregular polygons, not only rectangles. Room outline is logical space geometry. Provide actions to generate initial wall segments, floor surface and optional ceiling. Generated geometry must retain source-outline identity; manually edited segments remain editable without silently overwriting the original outline. Support line segments, circular arcs and Bezier curves in data structures. Use metres. Send geometry to:
curl -X POST "$API_BASE/Home_Security/Spatial/Properties/1/geometry" -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"kind":1,"name":"Study outline","geometryJson":"{"type":"polygon","points":[[0,0,0],[4,0,0],[4,0,3],[0,0,3]]}","height":2.8,"thickness":0}'
Do not claim exact solid collision checking client-side; backend validation is authoritative.

PROMPT 12 - Real-time updates through existing SignalR
========================================================================================
Use the existing authenticated SignalR hub `/HomeSecurityHub`; do not create a new hub. Connect using:
const connection = new signalR.HubConnectionBuilder().withUrl(`${API_BASE}/HomeSecurityHub`, { accessTokenFactory: () => token }).withAutomaticReconnect().build();
await connection.start();
await connection.invoke("AddPersonRole", token);
Listen for `SpatialSceneChanged`, `SpatialPlacementChanged`, and `SpatialVisibilityChanged`. Refresh only the affected property/scene using the authorized GET endpoint. Existing backend RealtimeNotificationService sends person-targeted notifications to a SignalR group keyed by PersonId; AddPersonRole(token) joins that group. Never broadcast private geometry to all users. Handle reconnect by invoking AddPersonRole again after successful reconnection.

========================================================================================

Use entity Version values for optimistic concurrency when supported by API responses; show a conflict dialog and reload the affected object rather than silently overwriting. Group related geometry operations into one user action. Support undo/redo locally until a server save is confirmed. Never treat a local optimistic update as persisted before API success.
